# 07. ADMISSION & RESIDENT WORKFLOW — VARAHI GIRLS HOSTEL

## 1. End-to-End Resident Lifecycle

The resident journey in DEVI Hostels progresses through seven distinct lifecycle stages:

```
[1. Public Enquiry] ---> [2. Staff Review & Visit] ---> [3. Admission Approval]
                                                               |
[6. Check-Out / Settlement] <--- [5. Active Stay & Billing] <--- [4. ID & Bed Allocation]
```

---

## 2. Detailed Workflow Stages

### Stage 1: Public Enquiry
- Prospective applicant (Student or Airport Employee) submits the mobile-responsive form on `/enquiry`.
- System captures full personal details, emergency contact, preferred branch (1–5), sharing type (1–4 sharing), target joining date, and category-specific metadata.
- Record stored in `enquiries` table with status `new`.

### Stage 2: Lead Triage & Contact
- Branch Manager or Warden receives notification on `/admin/enquiries`.
- Staff phones applicant, arranges physical room visit, and transitions status:
  `new` -> `contacted` -> `visited`.
- Staff logs call notes and candidate preferences into `internal_remarks`.

### Stage 3: Admission Confirmation & Allocation
When applicant confirms admission:
1. Manager selects target Branch (1–5), Floor (1–6), Room, and specific Bed (verified `vacant`).
2. Confirms actual Check-In Date and agreed Monthly Rent.
3. System triggers atomic ID generation function:
   - Queries `resident_id_sequences` with row lock.
   - Increments counter.
   - Formats `DV[BRANCH]-[FLOOR]-[SERIAL]`.
4. Creates record in `residents` and active record in `stays`.
5. Updates bed status to `occupied`.
6. Generates initial security deposit invoice and pro-rated/monthly rent invoice.
7. Enquiry status updated to `approved` with `converted_resident_id`.

### Stage 4: Check-In & Onboarding
- Resident arrives with physical government ID (Aadhaar/Passport/Airport AEP/College ID).
- Warden uploads document scans to Supabase Storage `resident-documents/`.
- Resident account activated; SMS/WhatsApp dispatched with Resident ID and initial login instructions.

### Stage 5: Active Stay & Continuous Operations
- Monthly joining-date billing runs automatically.
- Resident accesses self-service portal to review rent invoices, pay via UPI/Cards, and report maintenance requests.
- Room/Branch transfers are tracked by closing the current `stays` record (`is_current = false`, `check_out_date = NOW()`) and creating a new `stays` record. The permanent `resident_id` is never modified.

### Stage 6: Notice & Vacating
- Resident submits 30-day notice via Resident Portal.
- Room inspection performed by Warden.
- Outstanding rent, damages, or utility adjustments offset against refundable Security Deposit in the settlement ledger.
- Bed status marked `vacant`; `stays` marked closed; resident marked `inactive`.
