# 02. PRODUCT REQUIREMENTS — VARAHI GIRLS HOSTEL

## 1. Functional Requirements

### FR-01: Multi-Branch Centralized Administration
- The system must govern all five branches (Girls Hostel 1–4 and Girls Hostel 1) in a single unified web application.
- Branch Managers and Wardens must only access data scoped to their assigned branch, while Owners and Accountants can query and report across all branches.

### FR-02: Public Web Presence & Information Hub
- High-performance, SEO-optimized public pages showcasing DEVI Hostels: Home, About Us, 5 Branch detail pages, Student accommodation features, Airport employee accommodation features, Facilities & Amenities, Photo Gallery, FAQs, Contact Us, and Admission Enquiry.
- Clean mobile-first design with WhatsApp floating contact and click-to-call integrations for Owner E. Bharath Chandra.

### FR-03: Multi-Step Admission Enquiry Pipeline
- Responsive, interactive enquiry form capturing candidate contact info, category selection (College Student vs. Airport Employee), room-sharing preference (1, 2, 3, 4-share), preferred branch, and prospective joining date.
- Dynamic conditional fields:
  - *Students:* College name, course/branch, academic year, parent/guardian contact phone.
  - *Airport Employees:* Employer/airline name, job designation, work shift timing (Day/Night/Rotational), optional employee ID.
- Admin dashboard to review, filter, update enquiry stage (`new`, `contacted`, `visited`, `approved`, `rejected`), append timestamped internal staff notes, and convert approved leads directly into resident records.

### FR-04: Resident Identification Standard (Mandatory)
- Permanent, immutable format: `DV[BRANCH_CODE]-[FLOOR_NUMBER]-[UNIQUE_NUMBER]`.
- Floor number and branch code frozen from initial allocation.
- Centralized atomic counter ensuring sequential, gapless, zero collision IDs (e.g. `DV1-1-00001`).

### FR-05: Room & Bed Inventory Management
- Hierarchical schema: `Branch` -> `Floor` -> `Room` -> `Bed` -> `Resident`.
- Real-time tracking of occupied, vacant, reserved, and maintenance beds.
- Database-level constraint preventing double-allocation of any bed.

### FR-06: Dual Resident Authentication
- Method A: Mobile Phone Number + OTP.
- Method B: Resident ID + Secure Password.
- Both routes authenticate against the same single resident account.

### FR-07: Joining-Date Recurring Billing Engine
- Individual 30/31-day billing cycle anchored to the resident's confirmed joining date (e.g. 15th Nov to 14th Dec).
- Month-end edge-case handling (joining on 29th, 30th, 31st) using fixed end-of-month logic without drift.
- Separate accounting ledgers for Advance Rent vs. Refundable Security Deposit.

### FR-08: Omnichannel Payments & Reconciliation
- Integrated online payments (UPI, Cards, Netbanking) via Razorpay/Cashfree.
- Webhook signature verification and idempotency protection.
- Authorized offline payment ledger for Cash and Direct UPI transfers with mandatory maker-checker receipt verification.

### FR-09: Automated Notification System
- Triggered WhatsApp, Email, and SMS notifications for admission approval, monthly rent dues (-5d, -2d, 0d), overdue alerts (+2d, +7d, +15d), payment receipts, and security deposit releases.

## 2. Non-Functional Requirements

### NFR-01: Security & Compliance
- Strict Supabase Row Level Security (RLS) on all PostgreSQL tables.
- Zero credential leakage: API secrets, service keys, and payment tokens confined strictly to server-side routes / environment variables.
- HTTPS enforced across all endpoints.

### NFR-02: Performance & Scalability
- Sub-1.5 second First Contentful Paint (FCP) on public web pages.
- Database indexed on foreign keys, resident IDs, enquiry phone numbers, and payment status.

### NFR-03: Reliability & Data Integrity
- Database ACID transactions for all monetary allocations (Invoice -> Payment -> Advance/Deposit adjustments).
- Immutable audit log tracking sensitive changes (room transfers, fee adjustments, status updates).

### NFR-04: Responsiveness & Accessibility
- Seamless operation across desktop, tablet, and smartphone viewports (minimum 360px width).
