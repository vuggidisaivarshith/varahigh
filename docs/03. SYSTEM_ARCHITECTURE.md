## 2. Layered Component Boundaries

### 2.1 Presentation & UI Layer
- Built with React Server Components (RSC) by default for SEO, rapid initial page loads, and zero-bundle server logic.
- Client components (`'use client'`) used for rich interactive islands: multi-step enquiry form, room visualizer, dynamic filter dropdowns, payment modals.
- Design tokens defined in Tailwind CSS configuration with a warm, hospitable, professional palette tailored for DEVI Hostels.

### 2.2 BFF (Backend-for-Frontend) & Server Action Layer
- Server-side validations using Zod schemas to ensure inputs are strictly typed and sanitized.
- Safe credential encapsulation: API secret keys (`SUPABASE_SERVICE_ROLE_KEY`, `RAZORPAY_SECRET_KEY`, `WHATSAPP_API_TOKEN`) never reach browser client code.

### 2.3 Database & Storage Layer
- Managed PostgreSQL instance with native JSONB support for variable document metadata, precise `NUMERIC(10,2)` money representation, and timestamping with timezones.
- Row-Level Security (RLS) ensures residents only see their own records (`auth.uid() = resident.profile_id`), while branch staff only read/write records matching their assigned `branch_id`. Owner has global bypass privileges.

---

## 3. Data Integrity & Concurrency Controls
1. **Resident ID Centralized Counter:** Implemented as a dedicated atomic sequence table with row-level locking (`SELECT ... FOR UPDATE`) to guarantee zero collision even under concurrent admission confirmations.
2. **Bed Double-Allocation Guard:** Bed status is validated and locked within a single transaction during room allocation.
3. **Webhook Idempotency:** Payment gateway transaction IDs are stored with unique constraints; duplicate webhook deliveries return `200 OK` without triggering double balance adjustments.
