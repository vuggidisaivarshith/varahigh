# 05. RESIDENT ID SPECIFICATION — VARAHI GIRLS HOSTEL

## 1. Format Standard

The DEVI Resident ID is an immutable, human-readable, collision-proof identifier strictly adhering to the following structure:

$$\mathbf{DV[BRANCH\_CODE]-[FLOOR\_NUMBER]-[UNIQUE\_NUMBER]}$$

### Examples:
- `DV1-1-00001` (Girls Hostel Branch 1, Floor 1, Serial 1)
- `DV2-3-00125` (Girls Hostel Branch 2, Floor 3, Serial 125)
- `DV3-2-00045` (Girls Hostel Branch 3, Floor 2, Serial 45)
- `DV4-5-00076` (Girls Hostel Branch 4, Floor 5, Serial 76)
- `DV5-1-00089` (Girls Hostel Branch 1, Floor 1, Serial 89)

---

## 2. Component Definitions

### 2.1 Prefix
- Constant: `DV` (representing **VARAHI GIRLS HOSTEL**).

### 2.2 Branch Code (`[BRANCH_CODE]`)
Strictly single digit representing the resident's *initial admission branch*:
- `1` = Girls Hostel Branch 1
- `2` = Girls Hostel Branch 2
- `3` = Girls Hostel Branch 3
- `4` = Girls Hostel Branch 4
- `5` = Girls Hostel Branch 1

### 2.3 Floor Code (`[FLOOR_NUMBER]`)
Single digit representing the *initial floor of admission*:
- Values: `1`, `2`, `3`, `4`, `5`, `6`.

### 2.4 Unique Number (`[UNIQUE_NUMBER]`)
- Minimum 5 digits, zero-padded (e.g. `00001`, `00142`, `10450`).
- Generated from a centralized, monotonically increasing PostgreSQL sequence or locked counter table (`resident_id_sequences`).
- Never resets across branches or years.
- Never duplicated. Never recycled or re-issued upon resident departure.

---

## 3. Business & Technical Rules

1. **Permanent Assignment:** Generated strictly upon confirmed admission and initial bed allocation.
2. **Immutability upon Transfers:** If a resident moves from Branch 1 Floor 1 to Branch 2 Floor 3, their Resident ID remains `DV1-1-XXXXX`. Physical location history is tracked in the `stays` table.
3. **Display Mandate:** The ID must be prominently displayed on all:
   - Digital and printed rent invoices.
   - Payment receipts.
   - Resident dashboard and profile.
   - Resident digital ID card.
4. **Security Isolation:** The Resident ID is a public operational identifier and must NEVER be used as an authentication password or credential secret.
5. **Database Enforcement:** Enforced by a `UNIQUE` constraint on `residents(resident_id)`.
